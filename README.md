# Data Merge

This project is a monorepo designed to streamline the process of combining diverse data sources. It provides a structured environment with a dedicated frontend for user interaction and a robust backend service for performing complex data merging operations. Developers can leverage this system to efficiently integrate and manage various datasets.

## Features

*   **Monorepo Architecture:** Utilizes [pnpm](https://pnpm.io/) and [Turbo](https://turbo.build/) for efficient dependency management, faster builds, and optimized development across multiple applications and packages.
*   **Frontend Application:** A [Next.js](https://nextjs.org/) application built with [React](https://react.dev/) and [TypeScript](https://www.typescriptlang.org/) for intuitive user interfaces and data visualization.
*   **Backend Service:** A [TypeScript](https://www.typescriptlang.org/)-based backend application designed to handle data processing, merging logic, and API requests.
*   **Shared UI Component Library:** A dedicated package (`packages/ui`) built with [shadcn/ui](https://ui.shadcn.com/) for consistent and reusable UI components across applications.
*   **Structured Data Management:** Includes dedicated folders (`data/raw`, `data/metadata`) for organizing source data and associated metadata, facilitating clear input/output for merge operations.
*   **Centralized Configurations:** Shared [ESLint](https://eslint.org/) and [TypeScript](https://www.typescriptlang.org/) configurations (`packages/config`) ensure code consistency and type safety throughout the monorepo.
*   **Theming and Styling:** A dedicated theme package (`packages/theme`) likely using [Tailwind CSS](https://tailwindcss.com/) for consistent styling.

## Tech Stack

*   **Monorepo:** [Turbo](https://turbo.build/), [pnpm](https://pnpm.io/)
*   **Frontend:** [Next.js](https://nextjs.org/), [React](https://react.dev/), [TypeScript](https://www.typescriptlang.org/), [Tailwind CSS](https://tailwindcss.com/)
*   **Backend:** [TypeScript](https://www.typescriptlang.org/), [Node.js](https://nodejs.org/)

## Installation

To set up the project locally, follow these steps:

1.  **Clone the repository:**

    ```bash
    git clone https://github.com/theharshalchaudhari/data-merge.git
    cd data-merge
    ```

2.  **Install dependencies:**
    This project uses `pnpm` as its package manager. Ensure you have `pnpm` installed globally. If not, you can install it via npm: `npm install -g pnpm`.

    ```bash
    pnpm install
    ```

3.  **Start the development servers:**
    This command will concurrently start both the frontend and backend applications in development mode.

    ```bash
    pnpm dev
    ```

4.  **Build for production (optional):**
    To create optimized production builds for all applications and packages:

    ```bash
    pnpm build
    ```

## Usage

After running `pnpm dev`, the development servers will be active:

*   **Frontend:** The Next.js application will typically be accessible at `http://localhost:3000`. You can open this URL in your browser to interact with the user interface for data merging.
*   **Backend:** The backend service will run in the background, providing APIs consumed by the frontend. Its exact port may vary, but it will be configured to communicate with the frontend.

Details on specific data merging operations, configurations, and API endpoints would typically be found within the `apps/backend` service documentation or directly configurable through the frontend interface.

## Project Structure

The repository is organized as a monorepo with the following key directories and files:

*   `apps/`: Contains independent applications within the monorepo.
    *   `apps/backend/`: The TypeScript backend service responsible for data processing and merging logic.
    *   `apps/frontend/`: The Next.js application that provides the user interface.
*   `data/`: Stores data relevant to the merging process.
    *   `data/metadata/`: Holds metadata definitions or configuration for various data sources.
    *   `data/raw/`: Contains raw input data files that are targets for merging.
*   `packages/`: Houses reusable code packages shared across the applications.
    *   `packages/config/`: Centralized ESLint and TypeScript configurations to maintain consistency.
        *   `eslint-config/`: Shared ESLint rules.
        *   `typescript-config/`: Base TypeScript configurations.
    *   `packages/theme/`: Defines shared styles and theming for the frontend, likely including Tailwind CSS configurations.
    *   `packages/types/`: Contains common TypeScript type definitions used across the entire monorepo.
    *   `packages/ui/`: A UI component library built with shadcn/ui for consistent user experience.
*   `pnpm-lock.yaml`: The lock file generated by pnpm to ensure consistent dependency versions.
*   `pnpm-workspace.yaml`: Defines the monorepo workspace for pnpm, specifying which directories contain packages.
*   `security.md`: Document outlining the project's security policy and vulnerability reporting guidelines.
*   `setup-implementation.sh`: A shell script, likely for initial setup or deployment tasks (content not provided).
*   `turbo.json`: Configuration file for Turbo, managing task execution and caching within the monorepo.
